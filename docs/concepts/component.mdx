`agentphone-convex` is distributed as a self-contained Convex component — a unit of reusable backend logic that combines a typed API client, Convex-native database tables, and scheduled actions into a single installable package. You mount it into your application once and it manages its own state, scheduled work, and HTTP routes entirely within that boundary, keeping your own tables and logic cleanly separate.

## What the component bundles

The component ships three tightly coupled layers that work together automatically:

<CardGroup cols={3}>
  <Card title="Typed API client" icon="code">
    The `AgentPhone` class wraps every AgentPhone REST endpoint with a fully typed TypeScript interface. You call its methods from your own Convex actions and mutations — no raw `fetch` required.
  </Card>
  <Card title="Convex-native state" icon="database">
    Scoped tables for agents, numbers, conversations, messages, calls, transcripts, recordings, webhook deliveries, outbound request queues, and an immutable event log. These tables live inside the component boundary and are never directly accessible from your application code.
  </Card>
  <Card title="Scheduled actions" icon="clock">
    Durable outbound work queues with retries, idempotency, and observable status. Webhook delivery dispatching and retry logic also run as scheduled actions inside the component.
  </Card>
</CardGroup>

## Mounting the component

You register the component in `convex/convex.config.ts` using the standard Convex `app.use()` API. You only need to do this once per deployment.

```ts
// convex/convex.config.ts
import { defineApp } from "convex/server";
import agentphone from "agentphone-convex/convex.config.js";

const app = defineApp();
app.use(agentphone);
export default app;
```

After mounting, create a shared client in your `convex/` directory. The client is imported by your own Convex functions whenever they need to talk to AgentPhone or query the mirrored state.

```ts
// convex/agentphone.ts
import { AgentPhone } from "agentphone-convex";
import { components } from "./_generated/api.js";

export const agentphone = new AgentPhone(components.agentphone, {
  defaultAgentId: process.env.AGENTPHONE_AGENT_ID,
  defaultNumberId: process.env.AGENTPHONE_NUMBER_ID,
  scope: "default",
});
```

<Note>
  The `components.agentphone` reference is generated by the Convex CLI when you run `npx convex dev`. It provides the typed bridge between your application code and the component's internal functions.
</Note>

## The component boundary

The component's internal tables — `agents`, `numbers`, `conversations`, `messages`, `calls`, `callTranscripts`, `callRecordings`, `events`, `webhookDeliveries`, and `outboundRequests` — exist in an isolated namespace. Your application's own tables cannot read or write them directly.

All access to component state flows through the `AgentPhone` client class. For example, you never query the `messages` table directly with `ctx.db.query("messages")`; instead you call `agentphone.listLocalMessagesByConversation(ctx, { conversationId })` from within a Convex query or mutation. This indirection is intentional — it means the component can change its internal schema without affecting your application code.

<Tip>
  Because component state is fully isolated, you can safely use `agentphone-convex` alongside other Convex components in the same deployment without any risk of table name collisions.
</Tip>

## What you own vs. what the component owns

| Responsibility | Your app | Component |
|---|---|---|
| User authentication and authorization | ✅ | ❌ |
| Business logic and application tables | ✅ | ❌ |
| AgentPhone resource mirrors | ❌ | ✅ |
| Webhook verification and delivery | ❌ | ✅ |
| Outbound queue and retry logic | ❌ | ✅ |
| Event history log | ❌ | ✅ |

Your application calls the `AgentPhone` client from Convex actions, mutations, and queries, and the component handles everything below that interface. You are responsible for authenticating your users and deciding which data they are allowed to see before passing any results out of your Convex functions.
